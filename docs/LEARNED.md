## Lessons

- 2026-07-10: Never `git add -A` in this repo — check `git status` for untracked files first; the `!public/**` gitignore negation lets user bank saves slip into commits (trigger: committed and pushed Bank 1.imweb with a Phase 10 fix).
- 2026-07-11: After npm-installing a dep, check `npm ls <pkg>` for hoisted forks (obsidian-dataview pins lishid's @codemirror/language fork) and restart the Vite dev server — its pre-bundled deps cache (node_modules/.vite) goes stale and silently mixes old/new module instances (trigger: CodeMirror highlighting produced zero token spans; parse tree was fine).
- 2026-07-11: A failing headless DOM check is a real signal until proven otherwise — verify with a positive control before blaming the environment (trigger: dismissed zero CodeMirror highlight spans as a headless artifact; the legacy clike mode was genuinely broken in real Chrome too).
- 2026-07-12: Before writing any integration against an external AI provider API, read the current API reference/skill FIRST — model IDs, response shapes (thinking-first content blocks), and token semantics drift; building from memory cost five reactive bugfix phases (trigger: content[0].text parse bug + stale model list found only after real-provider failures).
- 2026-07-12: Never start a second dev server — share the owner's on 5173. A parallel server splits localStorage per port (API keys, presets invisible across origins) and masquerades as app bugs (trigger: killed owner's vite, spawned my own; test-connection 'paradox' was config split across 5173/5174).
- 2026-07-12: When adding behavior to a system-level entry point, grep for sibling paths that bypass it before claiming coverage — ps.setNormalized resolved tables but nearly every controller called p.setNormalized directly, so tables silently never applied to MIDI/mouse/sound (trigger: owner asked "do tables auto-scale?"; the honest answer was "they mostly don't run").
- 2026-07-30: "Append-only" protects a list's own indices, not indices in a list built by appending something AFTER it — before appending to SOURCE_DEFS, check every derived array with a tail (CAPTURE_SOURCES pins FG/BG/DS Src at SOURCES.length, so source 29 would have rotated them to 30/31/32 in five saved capture params). Stamp the base in the file and migrate on load; a frozen high base puts holes in dropdowns and controller travel (trigger: Blueprint §6 instructed "append at index 29" and nothing in the append-only rule flagged the collision).
- 2026-07-30: An exponential approach (slew, smoothing, easing) stored in a HALF-FLOAT buffer freezes short of its target — near 1.0 one ulp is ~1e-3, so once the per-frame step falls below that it rounds to no change and never arrives. Replace any step smaller than an ulp with exactly one ulp in the right direction, clamped against overshoot. And sample convergence at TWO horizons: a stall is indistinguishable from convergence if you only look once (trigger: rutt slew sat at 98.51 vs 100.91, bit-identical at frame 300 and frame 2000; the first guess was resampling through the history buffer, disproved by measuring the resampled-no-lag reference at 100.906).
- 2026-07-30: A new source must be wired into BOTH resolvers — `Pipeline._resolveSource()` (layers and mix buses; falls through to `inputs.color`) and main.js `_resolveLayerTex()` (engine-internal selectors like sdf.texSrc / td.mapSource / rutt.source; falls through to Output). Wiring only the second passes an audit that only checks the second, while routing the source to FG paints a solid frame in whatever hue the Color generator happens to be (trigger: Rutt-Etra rendered a flat RED screen on FG; audit reported a clean 30/30 because it parsed only _resolveLayerTex — it now checks both, and was confirmed to fail without the fix).
- 2026-07-30: Do not drive ImWeb's custom `.imw-sel` dropdowns by matching option text with a document-wide query — several menus can be in the DOM at once and the click lands in the wrong one, silently changing layer.fg (trigger: three scripted picks in a row hit the wrong selector and left the owner's live tab on Foreground=Fractal; use `.imw-sel-menu .imw-sel-item` scoped to the one open menu, or screenshot coordinates).
- 2026-07-30: Any geometry expanded AFTER projection (screen-space ribbons, billboards, thickness quads) has a winding that depends on where the camera is — set `side: THREE.DoubleSide` or it culls itself at some angles and not others. Reads as "the source is broken", not "the winding is backwards", when the dead angle happens to be the default (trigger: Rutt-Etra rendered nothing at rutt.angle 0 — its default — and fine at 65°; lit-pixel count was 0 with a forced-white fragment, which is what ruled out luminance and pointed at culling).
- 2026-07-30: Assert the RELATIONSHIP a control should have, with a direction, and pick a metric the control can actually move — then check the margin is not marginal. Three ways this went wrong in one feature: (a) beam width measured at 60 lines gave 1.16× across a 6× change because the lattice already filled the frame (saturated — at 8 lines it is linear to within 0.5%); (b) a gamma tested on lit-AREA gave a 43-pixel margin against a threshold of 40, which a dead knob would nearly pass; (c) the same gamma tested on vertical EXTENT gave 107 vs 107 on working code, because pow(0,g)=0 and pow(1,g)=1 leave a full-range ramp's endpoints invariant by construction — only the centroid moves; (d) a red-left/blue-right source has mean R == mean B by symmetry, so channel MEANS score a grey render and a fully chromatic one identically — measure per-pixel |R−G|+|G−B|+|R−B| instead (trigger: four wrong metrics across three knobs; two failed on correct code, one nearly passed on nothing, and one PASSED FOR THE WRONG REASON).
- 2026-07-12: An occluded/backgrounded Chrome tab freezes rAF entirely — render loop AND controller ticks stop; automated sweep tests read as failures while the code is fine. Check the app's FPS readout (0 fps = invalid test) before debugging the code (trigger: two "broken" recall-range test runs were just a hidden window).
- 2026-07-31: The one-canonical-source-list rule has a second failure mode nobody was watching: a param with its OWN short option menu, mapped to SOURCE_DEFS by a literal array of bare NUMBERS. `_sdfSrcToLayerIdx` was written against an older ordering and drifted three ways at once — "Draw"→3D Scene, "3D"→Noise, "Noise"→Color2, a solid cyan fill. Nothing flags it: every index is in range, every option resolves to a real texture, and it reads as an effect bug ("my glass metaball is blue"), not a routing bug. Map by KEY (`SOURCE_KEYS.indexOf('noise')`), never by number — a key cannot rotate under an append, and grep for source lists finds a key but not a `4` (trigger: owner reported a blue cast on Metaballs; the wrong texture was three menu entries away from the one named).
- 2026-07-31: Two verification traps in one session, both of which produce numbers that look fine. (a) A service worker (`imweb-v0.7`) serves a CACHED index.html on localhost, so `curl` returns the new markup while the tab renders the old — every new container id read as MISSING. Unregister the SW and clear caches before concluding a DOM change did not land. (b) `drawImage(webglCanvas)` into a 2D canvas returns a STALE frame without `preserveDrawingBuffer` — four different source selections gave bit-identical luma/chroma to 0.1 while the field was visibly animating. Identical readings across a knob that visibly moves means the READBACK is dead, not the knob; fall back to the screenshot tool.
- 2026-07-31: When a rename also changes UNITS, the property to test is not "did the keys change" but "does the thing still land in the same place" — assert the round trip against the consumer's own formula, then run it over the real saved file, not just fixtures. sdf.camX/Y/Z → orbit/elev/distance passed 45 of 45 camera maps in MasterProject.imweb at exactly 0 error, which is the only evidence that a migrated project opens looking identical. Corollary: a migration that DELETES the keys it reads needs no version stamp (the data answers "has this run?" itself) but that makes idempotency load-bearing, so test it explicitly. And carry only the settings that still mean the same thing — recall bounds in world units are meaningless on a 0–360° axis, so reset them rather than importing a ±1.4 sweep onto a parameter that runs to 360 (trigger: sdf camera rework; the owner's project had ctrlMin/ctrlMax and a response table on camX/camY).
- 2026-07-31: Defaults chosen to REPRODUCE the constant they replace are what make "expose this hardcoded value as a param" a safe change — decompose the literal instead of picking a round number. vec3(0.5,0.1,0.8) is HSV(274°, 0.875, 0.8); normalize(vec3(1,1.5,2)) is az 27° / el 34°; uv*0.75 is a 73.74° vertical FOV. Each default was derived, so no existing render moved (trigger: four hardcoded values exposed at once in the SDF shader).
- 2026-07-31: A new entry in an existing menu inherits an unwritten spec from its neighbours — MEASURE the family before adding to it. Five shapes appended to sdf.shape shipped at bounding radii 0.64/0.71/0.75/2.06/unbounded against a family that sits between 0.50 and 0.73, and the owner's first words on seeing them were "much larger than the older ones". Worse, two were wrong in KIND, not degree: a gyroid is triply-periodic and has no size of its own, so it ignored Size, Separation and Count and read as a background rather than a shape; a catenoid's flare is exponential, so its y clamp IS its size control (cosh(0.7/0.25) = a mouth 3.4x the family). Compute the bounding radius of every existing option and the new one before wiring the menu (trigger: shapes borrowed from Rutt-Etra's parametric list, sized from the source formulas instead of from the family they were joining).
- 2026-07-31: Never `await` a bare requestAnimationFrame from an automation probe — a backgrounded tab suspends rAF, the promise never settles, and the CDP call dies at its 45s timeout looking exactly like a frozen renderer. Two "renderer wedges" in one session were this, and the second one nearly got blamed on a giant unrolled shader. Race every rAF against a setTimeout, and check `document.hidden` FIRST: hidden means the render loop is stopped, so 0 fps, stale param readouts and a black canvas are all expected and every in-app observation is void (extends the hidden-tab entry above with the failure MODE, not just the symptom).
- 2026-07-31: `.imw-sel-trigger` TOGGLES its menu, so a probe that opens a menu and then fails leaves it open — and the next attempt CLOSES it, reporting "menus=0" forever. Reset any visible menu before opening. Also: the menu is `position:fixed`, so `offsetParent !== null` is ALWAYS false for it; test visibility with `style.display` + a non-zero rect (trigger: three consecutive "the dropdown will not open" failures, none of which were the app).
